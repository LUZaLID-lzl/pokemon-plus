# 宠物仓库与个体养成 · v0.34.16

| 功能 | 实现规则 |
|---|---|
| 庭院 | 保持最多5只；仓库按需增长，取消5＋11的宠物获取上限 |
| 仓库 | APP第一页进入；显示全部已拥有宠物，当前上场个体排在最前（最多5只），使用3px亮色重点边框，不显示场景文字；每页9只（3×3），显示昵称和等级；点卡片查看个体值、命名、放生、上场／替换；满5只时选择场景内交换对象，原个体回仓库 |
| 重复个体 | 同种／同家庭允许重复获得；每只独立保存状态、等级、形态、性格、个体值、昵称、永久不进化决定 |
| 性格 | 标准25种；非中性性格对应能力＋10%／−10% |
| 个体值 | HP／攻击／防御／特攻／特防／速度，各0–31，创建时随机一次；旧宠物迁移时补齐 |
| 战斗 | HP使用HP个体值；攻击和防御按招式的物理／特殊属性及性格计算；沿用玩家先手的轮流出招，速度暂不决定先手 |
| 命名 | 最多8个小写英文字母（a–z），仅小写键盘，删除／清空／保存三个按钮同排等宽；空名恢复形态名；旧存档的中文／大小写昵称仍可读取，重新编辑时大写字母转小写 |
| 咕噜球 | 商店30金币／个，使用与其他道具统一的32px像素图片，购买存入背包；普通野生战斗获胜后主动选择使用1球，必定捕捉 |
| 无球 | 保留待捕捉结果，可去商店购买再回来；可主动放走；不会自动转换额外奖励 |
| 蛋与初选 | 商店蛋、神兽挑战蛋不消耗球；初始三选一沿用免费初选；五只神兽仍只走八徽章挑战蛋 |
| 奖励 | 普通野外胜利仅一次结算25金币、30＋8×(对手等级−1)经验；捕捉仅授予个体，不重复发奖励 |
| 放生 | 仅未在场景中的个体可放生，必须二次确认；在场景中的个体可先收回，场景至少保留1只；不可撤销；历史图鉴和纯净之心等已得收藏不回退 |
| 真正空间不足 | 不设按天／家庭／数量的玩法限制；硬件NVS或内存耗尽时提示，捕捉不扣球，孵化保留蛋／药剂；通过放生腾出空间 |

界面统一显示庭院＋待命个体，合并计数和分页，未满行居中；72×66px卡片位于x66/144/222、y84/152/220，40px原生头像、12px昵称／等级；两侧翻页继续使用固定(18,158)／(298,158)的44px圆形按钮。底层`pp_warehouse_count/get`仍只表示待命区；场景个体不复制入库，继续由庭院槽位持久化。界面打开哪个个体，就对其真实槽位命名／收回／替换。

## 孵化揭晓 · v0.33.38

自然孵化和孵化药剂完成后进入独立「孵化成功」页，普通蛋和神兽蛋共用同一布局：96px开心动作、细环与像素星点，显示名字、等级、性格、六项个体值。底部「放入仓库」和「替换伙伴」左右对称，沿用原有个体和交换规则。页面动画不读图、不分配对象、不改变个体；计步等更新不会打断揭晓。实际共享LVGL截图：`screenshots/hatch-result.png`、`screenshots/hatch-result-stored.png`。

## 存档

v12冻结完整v11及更旧前缀，前11仓库位仍在旧布局内，额外条目动态分配。新增身份元数据与历史图鉴。序列化只保存固定数据和有效仓库记录，不保存指针／容量；完整载荷校验，损坏读入不替换当前游戏。

设备继续使用原24KiB NVS和16MiB分区。空间预算根据实际NVS总条目、其他命名空间占用、GC空页及两份原子快照计算，不是固定宠物数。新快照提交成功后清理旧版本键。显示锁内深拷贝复用仓库缓冲区，Flash写入在锁外；旧存档迁移不重新随机已有进度。v12及更新版本读取失败保留原键，禁止用默认游戏覆盖。

`pp_game`含动态记录，新增调用方须先`pp_init`或清零，用`pp_clone`深拷贝／`pp_save_write`和`pp_save_read`持久化；不再将整个结构直接写盘或以浅拷贝当独立仓库；结束调用`pp_dispose`。

## 陪钓伙伴
钓鱼页可从非场景仓库伙伴选择一只陪钓，按个体持续保存直到主动更换或取消。仍占仓库槽，不占场景位；当前陪钓者上场／放生前需先更换。整理、放生其他伙伴或改昵称不会改变选定个体。详见[FISHING.md](FISHING.md)。


从v0.34.11起，其他伙伴正在历练时，可以将仓库伙伴定点换入空闲庭院槽位。正在历练／旅行的目标、正在使用道具的目标及陪钓伙伴仍不可替换；历练期间不增减庭院人数，未看完的历练成长提示仍须先处理。固定槽位交换不移动其他宠物索引，不改变后台历练的参战对象／经验、旅行对象及结束时间。


## 仓库排序 · v0.34.16

底部返回按钮居中，右侧为44×44像素排序图标；两者沿用历练页的薄荷绿色像素风格，分别位于(158,288)与(208,288)，圆屏安全区内。排序不显示常驻文字，三种模式分别使用列表／递减等级条／分组方块，点击后短暂提示当前模式。

点击顺序：原序 → 等级 → 属性 → 原序。等级从高到低；属性读取当前进化形态，按一般、火、水、电、草、冰、格斗、毒、地面、飞行、超能、虫、岩石、幽灵、龙、恶、钢、妖精分组，先比较主属性，再比较副属性（无副属性排在前），同组内等级降序；完全相同时保持原仓库槽位顺序。原序恢复已有显示顺序。

当前在场景中的伙伴始终按庭院原槽位排在最前，最多五只，不参与排序；少于五只时后续仓库宠物直接接上，不留空位。切换模式回第一页，详情返回／重新打开仓库保留会话中的模式，重启恢复原序。排序仅生成显示索引，不移动实际庭院／仓库槽位，不写v17存档，不改变历练、旅行或陪钓对象；命名、放生、上场、替换仍作用于所点个体。临时内存分配失败回退原序并提示内存不足。

`tests/test_warehouse_sort.c`与对应`.mjs`覆盖320只、36页、稳定排序和151形态×60等级×2模式的C／Web键值一致；仓库真实指针smoke覆盖三种模式全部卡片、分页／回原序、排序后放生及历练／旅行中的空闲替换。截图：`screenshots/warehouse-sorting.png`。
